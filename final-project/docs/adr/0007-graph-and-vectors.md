# Графовое и векторное хранилища

## Статус

**Принято.** Онтология клиники и иерархия МКБ-10 — Neo4j 5. Семантический поиск чанков — Qdrant. Сессии, пользователи и связи `GUARDIAN_OF` — PostgreSQL.

## Разделение ответственности

| Задача | Хранилище | Обоснование |
|--------|-----------|-------------|
| Обход связей врач–услуга–подготовка–филиал; отношение PARENT кодов МКБ | Neo4j | язык Cypher; штатный Browser для эксплуатации |
| Выборка top-k с фильтром `acl` и `subject_id` | Qdrant | фильтрация до вызова LLM |
| Карточки, опека, слоты записи | PostgreSQL | персональные данные не размещаются в справочном графе МКБ |

## Варианты графового слоя

| Система | Преимущества | Ограничения | Решение |
|---------|--------------|-------------|---------|
| Neo4j | Neo4j Browser, APOC, поставка в виде контейнера | редакция Community достаточна для MVP | принято |
| Memgraph, FalkorDB | выше скорость на части нагрузок | меньше эксплуатационных практик в контуре | отклонено |
| Рекурсивные запросы PostgreSQL | одно хранилище | хуже обход иерархии МКБ | отклонено |

Векторный слой: Qdrant выбран относительно Milvus и Weaviate из-за простоты развёртывания в Compose и поддержки payload-фильтров. Файловый индекс FAISS отклонён: отсутствует сервис и фильтрация ACL.

## Решение

Оба хранилища находятся в Data Plane и не имеют маршрута в Интернет. Конвейер загрузки пишет в Neo4j и Qdrant. В runtime сначала применяется фильтр Qdrant, затем обход Neo4j по идентификаторам узлов, связанным с чанком.
