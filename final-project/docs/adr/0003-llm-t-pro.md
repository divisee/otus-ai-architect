# Выбор генеративной модели

## Статус

**Принято.** Основная модель: `t-tech/T-pro-it-2.1` (32B, Apache-2.0). Базовая архитектура — Qwen3-32B; использована дообученная сборка T-Bank с акцентом на русский язык и tool-calling.

Резервная модель того же класса: `Qwen/Qwen3-32B`. Для классификации намерения и фильтра «запрос на постановку диагноза» — модель класса 7–8B (T-lite либо Qwen3-8B).

## Контекст

Требования к модели:

1. Размещение в периметре (ADR-0001).
2. Качество на русском языке, включая термины МКБ и искажения ASR.
3. Устойчивый tool-calling для слотов CRM, обхода графа и эскалации.
4. Размещение на одном GPU H100 80GB в FP8 с запасом под контекст RAG и несколько вызовов в рамках одной реплики.
5. Лицензия, допускающая промышленное применение (не ограничение research-only).

Рассматривались открытые семейства с поддержкой русского языка: Qwen 2.5/3, DeepSeek, T-lite, Saiga. T-pro относится к линейке T-tech на базе Qwen3.

## Характеристики T-pro-it-2.1

Источник: [карточка модели](https://huggingface.co/t-tech/T-pro-it-2.1).

- `base_model: Qwen/Qwen3-32B`.
- Midtraining (~40B instruction-токенов), SFT (~670 тыс. примеров), GRPO по трём экспертам (instruction following, general, tool-call), объединение SLERP.
- Режим non-thinking: блоки `<think>` не генерируются; сокращается объём токенов перед TTS.
- Контекст 32 768 токенов; расширение YaRN ×4 — до приблизительно 128k.
- Токенизатор оптимизирован для русского языка относительно исходного Qwen3.
- Рантайм: vLLM (`--tool-call-parser hermes`). Сравнение движков — ADR-0005.

Следствие: вычислительный класс совпадает с Qwen3-32B; отличие — метрики на русском языке и на вызове инструментов.

## Решение

1. Промышленный контур: T-pro-it-2.1, FP8, H100 (ADR-0004).
2. Резерв: Qwen3-32B за тем же OpenAI-совместимым адресом.
3. Маршрутизация: модель 7–8B для классификации; ответ пользователю формирует модель 32B по допущенному контексту.
4. Системный промпт фиксирует роль ассистента клиники и запрет постановки диагноза. Параметры генерации — по карточке модели; для вызова слотов температура может быть снижена.

## Последствия

Преимущества: лицензия Apache-2.0; один GPU; замена на Qwen3-32B без изменения оркестратора.

Ограничения: нативный контекст 32k без YaRN меньше, чем у Qwen3-32B (128k); для MVP достаточно выборки узлов графа и top-n чанков. Квантование INT4 снижает качество относительно FP8. Опубликованные бенчмарки не являются медицинскими.

## Проверка

Набор из не менее 50 диалогов: запись на исследование, подготовка, разъяснение кода МКБ, отказ в доступе к чужой карте, запрос представителя о ребёнке. Критерии: доля ответов с опорой на извлечённый контекст не ниже 85%; доля валидных JSON tool-call не ниже 95%; p95 генерации не более 8 с на H100 FP8 при контрольной нагрузке.
