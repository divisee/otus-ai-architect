# Рамка первого промышленного контура (MVP)

Система — on-premise голосовой и текстовый ассистент медицинского центра. Функции: ответы по связанным знаниям клиники (GraphRAG), запись на приём, разграничение доступа в соответствии с 152-ФЗ и 323-ФЗ.

## Состав MVP

| Сценарий | Назначение |
|----------|------------|
| Ответы по услугам, врачам, филиалам, подготовке к исследованиям | извлечение из графа и чанков, не из весов модели |
| Запись, перенос, отмена визита через инструменты с подтверждением | HITL |
| Изоляция карточек: пациент не получает чужие сведения; законный представитель получает карту ребёнка | RBAC и ReBAC, ADR-0002 |
| Загрузка документов клиники в граф и векторный индекс | конвейер знаний |
| Речевой канал: ASR → тот же оркестратор → TTS | ADR-0009 |
| Отказ и передача оператору при отсутствии опоры в графе | ограничение галлюцинаций |
| Трассировка запроса и просмотр графа | эксплуатация и разбор инцидентов |

Онтология: `Doctor`, `Service`, `Preparation`, `Branch`, `IcdCode`. Справочник МКБ-10 не используется для постановки диагноза.

## Вне объёма MVP

- Постановка диагноза и подбор кода МКБ по симптомам.
- Интеграция с промышленной МИС; CRM — программная заглушка (Анна, Михаил, Борис).
- Обучение LLM и ASR.
- Отдельный продукт «чат на сайте»; текст доступен как API.
- Промышленная телефония (SIP, АТС); вход речи — микрофон или файл wav.
- Дообучение на корпусе диалогов, blue/green, ночная полная переиндексация как штатный процесс.

## Роли

| Идентификатор | Права |
|---------------|--------|
| `patient:anna` | собственная карта и карта сына (`GUARDIAN_OF`) |
| `patient:misha` | без самостоятельной учётной записи; запросы выполняет представитель |
| `patient:boris` | только собственная карта |
| `staff:registrar` | `public` и `staff` |
| оператор | эскалация при низкой уверенности |

## Голосовой канал

Общий Control Plane с текстовым API.

```
аудио → VAD → диаризация при числе говорящих больше одного → faster-whisper large-v3-turbo → Input Guardrails → LangGraph → Output Guardrails → Silero TTS
```

Интерфейс `/v1/chat` — основной для автотестов и нагрузки. `/v1/voice` — адаптер канала.

Стенд Control Plane собирается из `backend/` (см. [план](plan.md)). Генерация на CPU — grounded-порт; vLLM подключается без смены узлов оркестратора.

## Архитектурные ограничения контура

- Внешние API генеративных моделей не используются.
- Поиск знаний включает граф (Neo4j), не ограничивается векторным индексом.
- Разделение Control Plane и Data Plane.
- Оркестрация — LangGraph.
- Документы размещения и потоков данных: [Deployment](architecture/deployment.md), [Data Flow](architecture/data-flow.md).
